## 🎯 1. Цель

Нормализовать до третьей нормальной формы таблицу продаж сотрудников с заголовками
«Код сотрудника | Имя сотрудника | Месяц | Продажи | Код отдела | Название Отдела»,
устранив повторение имени сотрудника и названия отдела в каждой строке продаж.

## ⚠️ 2. Допущение по данным

**В исходном задании приведена только структура таблицы, строки не заданы; ниже использован демонстрационный набор данных, схема и правила 3NF соответствуют условию.**

Оригинал задаёт только три названия отделов: `Отдел реализации`, `Отдел развития`,
`Отдел экспорта`. Набор строк ниже придуман в том же стиле, что и данные лабораторных № 1/№ 2
(числовые коды, русские названия, даты 2026 года); он нужен только для того, чтобы показать
перенос данных и проверки. Месяц хранится строкой `ГГГГ-ММ`, продажи — суммой `DECIMAL(12,2)`.

| 2 | Петрова Мария | 2026-01 | 90000.00 | 20 | Отдел развития |

### Нарушения

1. **Повторяющиеся группы.** Имя сотрудника и название отдела дублируются в каждой строке месяца.
2. **2NF.** Ключ facts-строки — `(employee_id, sale_month)`; `employee_name`, `department_id`, `department_name` зависят только от `employee_id`.
3. **3NF.** Транзитивные зависимости: `employee_id → department_id → department_name`.
4. **Аномалии:**

| Аномалия | Что происходит в «плохой» таблице | Как исправляется в 3NF |
|----------|-----------------------------------|------------------------|
| Обновления | Переименование отдела в одной строке оставляет старое название в других строках | Название хранится один раз в `departments`, достаточно одного `UPDATE` |
| Удаления | Удаление всех строк сотрудника 4 стирает самого сотрудника (а отдел 10 остаётся только в чужих строках) | Сотрудник остаётся в `employees`, отдел — в `departments` |
| Вставки | Нельзя добавить отдел или сотрудника без продаж, не создав строку с `NULL` | `INSERT INTO departments/employees` работает без фактов продаж |

## 3. Целевая схема (3NF)

| Таблица | Назначение | Ключ |
|---------|-----------|------|
| `departments` | справочник отделов (`department_id`, `department_name`) | PK `department_id` |
| `employees` | сотрудники (`employee_id`, `employee_name`, `department_id`) | PK `employee_id`, FK → `departments` |
| `reporting_months` | справочник месяцев отчётности (`month_id`, `month_label`) | PK `month_id`, UNIQUE `month_label` |
| `employee_sales` | факты продаж (`employee_id`, `month_id`, `sales_amount`) | PK `(employee_id, month_id)`, FK → `employees`, `reporting_months` |

Справочник месяцев введён, чтобы выдержать тот же шаблон из четырёх таблиц, что и в
лабораторных № 1/№ 2, и хранить подпись месяца в одном месте; схема остаётся в 3NF.

## 📋 4. Шаги выполнения

1. `bash commands.sh` поднимает контейнер, очищает лог, выполняет скрипты и выгружает артефакты.
2. `01_schema.sql` создаёт БД `hr_sales_norm`, исходную таблицу и четыре пустые таблицы 3NF.
3. `02_seed.sql` загружает 7 демонстрационных строк в `employee_sales_unnormalized`.
4. `03_queries.sql`: перенос через `INSERT ... SELECT`, проверки, демонстрация аномалий
   в транзакции с `ROLLBACK`, удаление старой таблицы в конце.
5. Заполнить разделы 5 и 6 реальными результатами и скриншотами.

Ручной ввод SQL:

```bash
docker exec -it imfua-08-normalization-3 mysql --default-character-set=utf8mb4 -uroot -proot
```

## 📊 5. Результаты проверок (реальный запуск)

| Проверка | Ожидаемое значение | Фактический результат |
|----------|--------------------|------------------------|
| `SUM(sales_amount)` до нормализации | 715 000.00 | `total_old = 715000.00` |
| `SUM(es.sales_amount)` после нормализации | 715 000.00 | `total_new = 715000.00` |
| Отделов: `DISTINCT` / `COUNT(*) FROM departments` | 3 / 3 | `old_departments = 3`, `new_departments = 3` |
| Сотрудников: `DISTINCT` / `COUNT(*) FROM employees` | 4 / 4 | `old_employees = 4`, `new_employees = 4` |
| Месяцев: `DISTINCT` / `COUNT(*) FROM reporting_months` | 2 / 2 | `old_months = 2`, `new_months = 2` |
| Фактов: исходных / `COUNT(*) FROM employee_sales` | 7 / 7 | `old_sales = 7`, `new_sales = 7` |
| Продажи сотрудника 1 | 270 000.00 | `1	Иванов Иван	270000.00` |
| Продажи по отделу 10 | 340 000.00 | `10	Отдел реализации	340000.00`; также `20	Отдел развития	200000.00`, `30	Отдел экспорта	175000.00` |
| Аномалии после 3NF | переименование отдела — одна строка; сотрудник без продаж возможен | В «плохой» таблице отдел 10 показан как `Отдел продаж` и `Отдел реализации`; в `departments` после `UPDATE` одна строка `10	Отдел продаж`; после удаления продаж сотрудник `4	Кузнецова Анна	10` остаётся; `99	Отдел качества` добавлен без продаж |
