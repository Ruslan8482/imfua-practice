# 21. Jira

> **Важно:** для реального запуска необходим Docker. В этой среде Docker отсутствует:
> команды ниже — готовые инструкции, а не выполненные действия; значения в разделе
> «Результаты» — плейсхолдеры, которые заполняются после запуска на вашей машине.

> ## ⚠️ Предупреждение
>
> ВНИМАНИЕ: очень тяжёлый образ с длительной инициализацией (до 5–10 минут) и высоким потреблением памяти/CPU. Запускайте только при наличии ресурсов, данные админ-панели заполнять не требуется.

> Следуйте инструкции источника и запускайте только в изолированном окружении.

## Что за образ

Платформа для управления задачами из семейства DevOps-инструментов. Первый запуск инициализируется долго.

- **Образ(ы):** `atlassian/jira-software:latest`

### Порты

| Порт хоста | Порт контейнера | Назначение |
|---|---|---|
| `2990` | `8080` | веб-интерфейс Jira |

### Переменные окружения

Не используются.

## Предварительные требования

- WSL, другой полноценный Linux либо Git-Bash/Linux/Mac; для части команд — Windows PowerShell.
- Свободные порты из таблицы выше (проверять до запуска).
- Рекомендуется начать с «чистого листа»: остановить и удалить ненужные учебные контейнеры и образы.
- Никогда не используйте русские имена файлов/каталогов, пробелы и спецсимволы в путях проекта.

```shell
docker version
docker ps -a
```

## Пошаговое выполнение

### 1. Загрузка образа

```shell
docker pull atlassian/jira-software:latest
```

### 2. Запуск контейнера

```shell
docker run -d --name jira -p 2990:8080 atlassian/jira-software:latest
# альтернатива без :latest:
# docker run -d --name jira -p 2990:8080 atlassian/jira-software
```

### 3. Наблюдение за инициализацией

```shell
docker logs -f jira   # выход по Ctrl+C
```

### 4. Проверка работы

```shell
docker ps
curl -I http://localhost:2990/
# или открыть http://localhost:2990 в браузере после завершения подготовки
```

### Очистка контейнера

```shell
docker stop jira || true
docker rm -f jira || true
```

## Проверка работы (кратко)

- `docker ps` — контейнер в статусе `Up` (для `--rm`-контейнеров проверка во время работы).
- `curl <адрес>` или браузер — страница/ответ сервиса.
- `docker logs <имя>` — отсутствие ошибок в логах.
- `docker exec -it <имя> ...` — проверка изнутри контейнера (где предусмотрено заданием).
