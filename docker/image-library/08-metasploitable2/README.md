# 08. Metasploitable2

> **Важно:** для реального запуска необходим Docker. В этой среде Docker отсутствует:
> команды ниже — готовые инструкции, а не выполненные действия; значения в разделе
> «Результаты» — плейсхолдеры, которые заполняются после запуска на вашей машине.

> ## ⚠️ Предупреждение
>
> ВНИМАНИЕ: образ содержит уязвимости намеренно! Запускайте только в изолированном учебном окружении, без доступа к рабочей сети и производственным данным. Не публикуйте порты наружу и не используйте этот контейнер как рабочую систему.

> Следуйте инструкции источника и запускайте только в изолированном окружении.

## Что за образ

Специально уязвимая виртуальная машина Linux для обучения пентесту; запускается в интерактивном режиме.

- **Образ(ы):** `tleemcjr/metasploitable2`

### Порты

Порты не публикуются.


### Переменные окружения

Не используются.

## Предварительные требования

- WSL, другой полноценный Linux либо Git-Bash/Linux/Mac; для части команд — Windows PowerShell.
- Свободные порты из таблицы выше (проверять до запуска).
- Рекомендуется начать с «чистого листа»: остановить и удалить ненужные учебные контейнеры и образы.
- Никогда не используйте русские имена файлов/каталогов, пробелы и спецсимволы в путях проекта.

```shell
docker version
docker ps -a
```

## Пошаговое выполнение

### 1. Загрузка образа

```shell
docker pull tleemcjr/metasploitable2
```

### 2. Запуск и вход (Windows)

```shell
docker run --name metasploitable2 -it tleemcjr/metasploitable2
```

### 3. Запуск и вход (Linux: старт сервисов + bash)

```shell
docker run --name metasploitable2 -it tleemcjr/metasploitable2:latest sh -c "/bin/services.sh && bash"
```

### 4. Проверка работы внутри контейнера

```shell
hostname
uname -a
ps aux | head -20
```

### 5. Выход из контейнера

```shell
exit
```

### 6. Удаление образа (опционально)

```shell
docker rmi tleemcjr/metasploitable2
```

### Очистка контейнера

```shell
docker stop metasploitable2 || true
docker rm -f metasploitable2 || true
```

## Проверка работы (кратко)

- `docker ps` — контейнер в статусе `Up` (для `--rm`-контейнеров проверка во время работы).
- `curl <адрес>` или браузер — страница/ответ сервиса.
- `docker logs <имя>` — отсутствие ошибок в логах.
- `docker exec -it <имя> ...` — проверка изнутри контейнера (где предусмотрено заданием).
